# RPI house style

Follow explicit user choices and the project's established conventions first. These are house defaults, not a reason to migrate an unrelated project or broaden a small edit.

- For architecture, validation, and general coding, read [engineering](references/engineering.md).
- For Python, MATLAB, or R, read only the applicable section of [scientific languages](references/languages.md).
- For MySQL, read [database conventions](references/mysql.md).
- For tests, read [test quality](references/tests.md).
- For documentation and plans, read [technical writing](references/writing.md).

Keep exact units, dimensions, numeric precision, dependency versions, error contracts, and reproducibility requirements visible in both implementation and verification. Prefer specific composable code to speculative frameworks. Avoid unrelated style-only churn.
